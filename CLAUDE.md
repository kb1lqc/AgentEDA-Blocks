# circuit-blocks: agent rules

Reusable circuit blocks in Zener (`pcb` 0.4.x); components from `github.com/kb1lqc/zener-library`. Correctness beats speed; never guess a number. I review every diff; do not commit unless I ask. No PCB layout until I say layout has started.

Pointers: layout, ports, versioning, reuse `docs/spec/blocks.md`; report format `docs/spec/analysis-report.md`; schematic tools `tools/schematic/README.md`; schematic workflow `../zener-library/docs/briefs/schematic-capture.md`; skills `agent-roles`, `ee-design`, `reusable-blocks`, `schematic-style`, `zener-language`.

## Sources of truth
- `.zen` files, analysis Python and `params.json` only. Bench `design-analysis.*`, charts and `values.json` are generated by `python3 blocks/<Block>/analysis.py`; never hand-edit; `tools/check_reports.py` fails a stale one. Text cites a section or key, never a copied number.
- Part data lives in the library; never retype it here. Design intent: `spec.md`, then configs, `params.json`; each non-datasheet value is a DESIGN CHOICE with a basis.
- Circuit changes go in the `.zen`; KiCad edits are presentation only.

## Library checkouts
- `../zener-library`: pinned clean checkout at `ZL_VERSION` (`analysis/_zl.py`, or `$ZENER_LIBRARY`); used for analysis and reported results.
- `../diodecomputer`: in-progress working copy for library changes, released by tag, then picked up here; never for reported results.
- `ZL_VERSION` must be a release containing `docs/briefs` and `docs/spec`; bump with the deps. Versions are tool-managed (`pcb sync`, `pcb add`). `tools/check_env.py` enforces pcb-version, no nested `[workspace]`, clean tagged checkout, dep tags at or before `ZL_VERSION`.

## After every change
From the repo root: `pcb sync` (if imports changed; a hook runs `pcb fmt` on edited `.zen`), the affected `python3 blocks/<Block>/analysis.py`, then `python3 tools/verify.py [bench]` (env, builds with one logged retry, reports, sync): one PASS line or the first 5 failures, log path. Schematic gates: `python3 tools/verify.py --schematic <bench>`. Report every UNVERIFIED, waiver, open item.

Before any commit touching `.zen`, `pcb.toml`, `eda/*.kicad_sch` or a schematic PDF, `check_sync.sh` must print `IN SYNC`; the pre-commit hook enforces it; never `--no-verify`.

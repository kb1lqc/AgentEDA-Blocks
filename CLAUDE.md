# circuit-blocks: agent rules

A repository of reusable circuit blocks captured in Zener (`pcb` 0.4.x), used by board projects the way they use the
component library: imported by URL at a pinned version, analysed per instance, drawn as sheets on a block diagram.
Components come from `github.com/kb1lqc/zener-library` (the author's library; part data, equations and wrappers are
fixed there, not here). Correctness beats speed. Never guess a number. I review every diff; do not commit unless I
ask. Repository structure, standard ports, versioning and sheet reuse: the `reusable-blocks` skill.

## Layout
- `blocks/<Block>/`: one `pcb` package per block (`<Block>.zen`, `pcb.toml`, `spec.md`, `analysis.py`).
- `benches/<Block>/`: the block's bench board (`bench.zen`), its instance parameters (`params.json`), its arranged
  sheets (`eda/`, where `eda/<instance>.kicad_sch` is the block's reference sheet), generated analysis and
  `<bench name>.pdf` (`docs/`, named after the Board) and
  schematic note rules (`notes_rules.py`).
- `analysis/`: shared Python helpers (`_zl.py` loads the component library). No block-specific numbers.
- `tools/`: shared scripts (`schematic/check_sync.sh`, `update_notes.py`, `stamp_block.py`; `git/pre-commit`).

## Sources of truth
- **Only `.zen` files, the analysis Python and the params files are sources of truth.** Each bench's design-analysis
  datasheet (`benches/<Block>/docs/design-analysis.md`, `design-analysis.pdf`, charts, `values.json`) is GENERATED by
  `python3 blocks/<Block>/analysis.py`; never hand-edit it. The block spec and schematic notes quote it; `.zen`
  comments and spec text cite a section or values key rather than copying numbers.
- **Part data and datasheet equations** live in the library's `component.toml` / `calc.py`. Never retype a datasheet
  number or equation in this repo. A missing or wrong part number is a library change, made in the library repo
  (local working copy: `../diodecomputer`), released with a new tag, then picked up here.
- **Design intent** (rails, ranges, gains, current limits, ambient) lives in the block's `spec.md` first, then as
  named configs on the block and values in the bench's `params.json`. Every non-datasheet value is a DESIGN CHOICE
  with a basis.
- **Analysis** (worst case, nominal) is Python, loading parts through the library's `lib`
  (`from analysis import _zl` then `from lib import load, Param, wca, table`). Compute component values there from
  `calc.py`; snap in Zener with the stdlib E-series helpers.

## Design approach and schematic style
- Engineering approach (worst-case analysis, self-heating, BOL shifts, calibration, error stack-ups, fewest parts,
  BOM value reuse, 0603+, 100 nF per power pin, SPI source termination, availability, when to ask): `ee-design`.
- Schematic drawing and review: `schematic-style`; order of work and gates: `schematic-capture`.
- Skills live in zener-library (`.claude/skills/`) and are linked into `~/.claude/skills/`. Repository-specific style
  observations go in `docs/style-notes.md` first; generic ones are promoted to the skills.
- Schematic phase: no PCB layout work (`pcb layout`, `.kicad_pcb`) until I say layout has started.

## Library version pinning
- Zener deps: each block's `pcb.toml` `[dependencies]`, tool-managed. Never hand-edit versions; use `pcb sync`,
  `pcb list -m -u`, `pcb add -u`, or `pcb add <url>@<version>` run inside the block folder.
- Python: `analysis/_zl.py` `ZL_VERSION`, checkout at `../zener-library` (or `$ZENER_LIBRARY`). Keep it equal to
  the Zener dep versions; bump both together. Never point it at the in-progress `../diodecomputer` tree for results
  that go in a report.
- Never put the library (submodule or copy) inside this repo: `pcb` fails on any nested `[workspace]` pcb.toml,
  hidden or git-ignored included.
- Releasing a block: tag `blocks/<Block>/vX.Y.Z`; boards pin the Zener package and the analysis at the same tag.

## Zener rules
- Use the `zener-language` skill (`.claude/skills/zener-language/`) for syntax. Confirm any construct in the stdlib
  source (`pcb list -m -json @stdlib`) or `pcb <cmd> --help` before using it; there is no `pcb doc`.
- Import parts by full URL: `Module("github.com/kb1lqc/zener-library/components/<Mfr>/<Value>/<Value>.zen")`; benches
  import their block by full URL too (`github.com/kb1lqc/circuit-blocks/blocks/<Block>/<Block>.zen`, resolved locally
  as a workspace member). Relative paths that leave a package fail.
- Give every checked net a voltage with tolerance (`Power("V5", voltage="5V 5%")`). An undeclared voltage reports
  UNVERIFIED and fails `-Dwarnings`.
- Pass `ambient` and `derate` down to every wrapper and through every block. Never hard-code them. A `waive_<key>`
  needs a rationale with a cite and is listed in the report.
- Keep topology stable: configs change values and `dnp`, never add, remove or reconnect instances. Ports use the
  standard names in `reusable-blocks`.
- Prefer stdlib generics for passives/connectors/test points unless a library series part is needed for analysis
  (e.g. precision resistors, the shunt).

## After every change
From the repo root, judging by exit code:
`pcb fmt <file>` -> `pcb sync` (if imports changed) -> `pcb build -Dwarnings benches/<Block>/bench.zen` -> the
affected `python3 blocks/<Block>/analysis.py`. Delete `__pycache__/` afterwards. Report every UNVERIFIED, waiver and
open item.
The first `pcb build` after a `pcb.toml` change has been seen to fail once without diagnostics; re-run
before concluding anything.
After committing sheet changes: `python3 tools/schematic/stamp_hash.py`, `tools/schematic/export_pdf.sh`, commit
"Stamp sheet hashes" (each sheet's title-block hash is the commit that last changed its content).
For a design-value change: edit the analysis, params or `.zen`; run `python3 blocks/<Block>/analysis.py`
(regenerates the bench datasheet and `values.json`), then `python3 tools/schematic/update_notes.py benches/<Block>`
(schematic notes from the values, no hand typing), then `pcb apply schematic --no-open benches/<Block>/bench.zen`
twice, netlist diff, build, ERC, `tools/schematic/export_pdf.sh` (any sheet change, notes included).
**Sync check (mandatory):** `tools/schematic/check_sync.sh` (all benches) must print `IN SYNC` before any commit that
touches `.zen`, `pcb.toml`, `*/eda/*.kicad_sch` or a schematic PDF; it also fails on a stale bench PDF or a stale `design-analysis.pdf` (`python3 -m analysis.md_pdf --check`). The pre-commit hook (`tools/git/pre-commit`, enabled by
`git config core.hooksPath tools/git`) enforces it; never bypass it with `--no-verify`. Circuit changes go in the
`.zen`; KiCad edits are for presentation only (placement, wires as drawn, notes, boxes, title block).
